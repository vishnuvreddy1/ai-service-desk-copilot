# Power Automate Flow — Ticket Creation

## Overview
This flow is triggered by Copilot Studio when a user's issue cannot be resolved automatically and requires a support case to be created in Dynamics 365 Customer Service.

## Trigger
**Type:** HTTP Request (from Copilot Studio action)

**Input Schema:**
```json
{
  "type": "object",
  "properties": {
    "userId": { "type": "string", "description": "Entra ID object ID of the user" },
    "userName": { "type": "string", "description": "Display name of the user" },
    "userEmail": { "type": "string", "description": "Email address of the user" },
    "category": { "type": "string", "description": "Ticket category: PasswordReset | AccessRequest | SoftwareInstall | HardwareIssue | General" },
    "description": { "type": "string", "description": "Summary of the user's issue from conversation" },
    "priority": { "type": "string", "description": "P1 | P2 | P3 | P4" },
    "conversationTranscript": { "type": "string", "description": "Full bot conversation transcript" }
  },
  "required": ["userId", "userName", "userEmail", "category", "description", "priority"]
}
```

## Flow Steps

### Step 1 — Parse Input
Parse the HTTP request body using the schema above.

### Step 2 — Get User from Dataverse
Look up the contact record in Dataverse by `userEmail` to retrieve the Contact ID for D365 case association.

```
Action: List rows (Dataverse)
Table: Contacts
Filter: emailaddress1 eq '<userEmail>'
```

### Step 3 — Determine Queue
Use a Switch expression on `category` to map to the correct D365 queue:

| Category | Queue Name |
|---|---|
| PasswordReset | IT-Tier1-Bot |
| AccessRequest | IT-Access |
| SoftwareInstall | IT-Software |
| HardwareIssue | IT-Hardware |
| General | IT-Tier1-Bot |

### Step 4 — Create D365 Case
```
Action: Add a new row (Dataverse)
Table: Cases (incidents)

Fields:
  title          = "Bot Escalation: <category> — <userName>"
  description    = <description>
  customerid     = <Contact ID from Step 2>
  prioritycode   = <mapped from priority P1→1, P2→2, P3→3, P4→4>
  casetypecode   = 1 (Question)
  new_source     = "Copilot Studio Bot"
  new_transcript = <conversationTranscript>
```

### Step 5 — Assign to Queue
```
Action: Perform a bound action (Dataverse)
Action Name: AddToQueue
Table: Queues
Row ID: <Queue ID from Step 3>
Parameters:
  Target: { "@odata.type": "Microsoft.Dynamics.CRM.incident", "incidentid": "<Case ID>" }
```

### Step 6 — Log Bot Interaction
```
Action: Add a new row (Dataverse)
Table: cr_botinteraction

Fields:
  cr_userid      = <userId>
  cr_caseid      = <Case ID from Step 4>
  cr_category    = <category>
  cr_resolved    = false
  cr_createdon   = utcNow()
```

### Step 7 — Return Response to Copilot Studio
```json
{
  "caseId": "<Case ID>",
  "caseNumber": "<Auto-generated case number>",
  "queueName": "<Queue Name>",
  "status": "created"
}
```

## Error Handling
- If Dataverse contact not found → create a new contact record first, then proceed
- If D365 case creation fails → retry 3 times with 30-second delay, then send alert email to IT admin
- All errors logged to Azure Application Insights

## Output
Returns the created case ID and case number back to Copilot Studio to confirm to the user.
